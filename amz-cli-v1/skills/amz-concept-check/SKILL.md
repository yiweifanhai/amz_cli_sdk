# Amazon 新品概念验证

目标是判断真实买家是否会购买，不是替发明人证明想法正确。

## 输入与边界

接受产品图、文字描述、目标关键词、目标价格、目标人群和设计理由的任意组合。

开始前只补最影响结论的信息，最多问 3 个问题：

1. 产品解决什么具体问题，谁最先需要？
2. 目标售价或价格区间是什么？
3. 与现有方案相比，用户能直接感知的变化是什么？

用户要求按假设继续时，记录假设，不反复追问。没有图片时，价值感知最高 5 分。

不评估利润、供应链、准入或 IP。用户给的是已上架 ASIN 且没有新品概念时，改用市场或产品分析入口。

## 数据路径

先读 `skills/amz/references/capabilities.md`，再按输入选择最小链路。

有目标关键词时，优先调用：

```bash
amz run entity.keyword.market_profile --param term="<keyword>" marketplace=US
amz run entity.keyword.market_opportunity --param term="<keyword>" marketplace=US
amz run entity.keyword.products --param term="<keyword>" marketplace=US
```

从返回商品中选 2-5 个使用场景、价格带和形态最接近的代表竞品。对每个竞品调用：

```bash
amz run entity.product.voc --param asin=<ASIN>
```

`entity.product.voc` 已聚合以下 Product 字段，不要再手工抓详情和评论：

- `strengths`：现有产品向用户承诺的优势。
- `weaknesses`：评论中的痛点、未满足需求和满意度背景。
- `use_insights`：真实使用场景、人群和购买动机。

新品描述已经足够完整，且有 3-5 个基准品数据时，可把完整临时数据交给
`analysis.innovation.compare`。新品还不是 Entity，不要伪造 ASIN 或写入 Product 缓存。

外部搜索只补 CLI 数据没有覆盖的内容：站外讨论、替代方案、退货原因和价格锚点。
优先找反面证据；每个市场判断保留来源链接和检索日期。最多 10 次搜索或 15 分钟。

## 判断方法

从图像与证据中先写出 2-3 个典型买家的第一人称决策过程，其中至少一个是怀疑者。
然后对四个维度各打 0-10 分：

- 需求真实性：用户是否主动表达这个问题。
- 受众清晰度：人群是否具体且可触达。
- 差异化感知：变化是否解决竞品的真实弱点，并能被用户看见。
- 价值感知：功能、质感和售价是否匹配。

总分取平均值，保留一位小数。任何维度不高于 3 时，总分封顶 5.0。总分至少 6.0 才通过。
证据不足时降低置信度，不把常识推断写成用户事实。

## 输出

输出中文 Markdown 报告，顺序固定为：

1. 一句话结论、结论标签和总分。
2. 最硬的支持或反对证据。
3. 真实目标用户与 2-3 个购买决策模拟。
4. 四维评分表，每个分数对应证据。
5. 具体改进、低成本验证方法和放弃信号。
6. 信息缺口、采用的假设及其影响。

结论标签只用“通过”“有条件通过”“不通过”。报告不能留下待回答问题。
