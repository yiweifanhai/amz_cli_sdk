# amz-cli 安装与安全配置

目标是让用户通过本机页面完成配置，不要求用户输入或理解命令。

## 流程

1. 运行 `amz version --json` 检查 CLI。若命令不存在，使用当前 amz 发布包根目录中的
   Windows 或 macOS/Linux 安装器。不要要求用户自己执行安装命令。
2. 运行 `amz setup --status --json`，只说明哪些服务已配置，不读取配置文件，也不输出密钥。
3. 需要新增或更换配置时，运行 `amz setup --web`。保持进程运行，等待用户在自动打开的
   本机页面中填写。分发版停止输入约一秒或离开输入框后自动保存，选择项立即保存；
   页面显示“已自动保存”后即可使用，无需点保存或等待服务退出。如果浏览器没有自动打开，
   把 CLI 输出的本机链接发给用户点击。源码基础页仍按其实际保存方式操作。
4. 用户确认页面显示自动保存成功后再次运行 `amz setup --status --json`，报告配置结果。状态 true 不能独立证明本次修改已保存；失败时先处理页面提示。不要复述任何密钥。

## SIF 的分发配置

- 在分发版配置页，默认填写老板或管理员提供的 Token，不要求普通使用者提供账号密码。
- 仅当用户明确要求生成 Token 时，说明可以展开“用账号生成 Token（老板 / 管理员）”。
  用户在本机页面输入手机号和密码，生成后立即自动保存并填入，可复制分发；账号密码不落盘。
- 同一页面复用生成结果。Token 过期时联系管理员更新，禁止自动登录或自动刷新共享账号。
- 此流程由发行包的 `setup_app.py` 提供，基础 CLI 只读取已保存 Token。源码直连的
  `amz setup --web` 可能没有分发扩展，不能声称所有安装方式都已有账号生成页。

## COSMO 图片开关

- 用户要求打开配置、开启或关闭 COSMO 图片抽取时，按上面的流程打开本机配置页。
- “COSMO 图片关键词抽取”统一控制全部主图、附图和 A+ 图，默认开启。
- 开启：图片缩放后与 Listing 一起抽取；关闭：只分析标题、五点、参数和文字描述。
- 分发版选择后立即自动保存。重新打开时显示已保存的选择；`setup --status --json`
  的 `cosmo_use_images` 返回当前开关。切换后下次 COSMO 调用按新设置重算缓存。
- 这是总开关；关闭时即使调用参数带图或 `use_image=true`，也不发送图片。
  开启时仍可用单次 `use_image=false` 只分析文字。不要在开关修改时更改其他凭据。

## 豆包模型配置

- 配置页只需一个豆包 / 火山方舟 API Key，程序按任务选择 Mini、Lite、Pro。
- 已保存的 Ark Key 可直接复用；无需要求用户再填一次相同密钥。
- COSMO 图片按比例缩到最长边 512 像素，与文字一起交给 Lite 直接抽取；原有深度分析任务保留 Pro。
- 状态“已配置”只表示存在 Key，不证明三款模型均有权限。调用失败要报告具体错误，
  不自动转用 DeepSeek、OpenRouter 或其他服务。旧服务的密钥仍保留，但不在新配置页展示。

## 安全约束

- 不要求用户把 API Key、Token 或密码粘贴到聊天中。
- 不用命令参数、环境变量或临时脚本传递密钥。
- 不读取或展示 `~/.amz/config.yaml` 的内容。
- 配置页必须是 CLI 启动的 `127.0.0.1` 地址。不要改成公网地址或远程表单。
- 空输入表示保留原配置。除非用户明确要求，不删除或覆盖其他服务的配置。
- 若用户已经在聊天中发送密钥，提醒其立即到服务商后台轮换，再通过本机配置页填写新密钥。
